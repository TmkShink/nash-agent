# Nash 视频脚本

## 成片定位

视频在约 101.4 秒内介绍 Nash 的完整使用链路：输入任务、实时接收模型输出、观察工具调用、查看 trace、执行独立 grader，再操作生成的 2048 页面。画面来自同一次真实运行，中文字幕只说明当前能力与正在发生的动作。

成片没有配音、背景音乐、封面和转场动画。面试播放时可以沿着字幕补充设计取舍，不需要逐字朗读。

## 面试时怎样讲

开头十秒只补一句：“任务、约束和验收都在同一条用户指令里，接下来没有人工接管代码。”

工具卡片出现时讲清双通道设计：“SSE delta 让用户及时知道 Agent 在做什么；真正执行工具前，runtime 仍会等待 `[DONE]`，聚合完整参数并做本地校验。”

grader 段强调证据边界：“Agent 只看到 7 项公开测试，停止后才加入 14 项 hidden tests。`21/21` 说明这份产物满足固定契约，不代表任意任务都能一次成功。”

浏览器段不用解释实现细节，直接说明键盘、pointer、分数、新游戏和 Best 的行为。面试官继续追问时，再进入引擎纯函数、随机数契约、DOM 测试和静态视觉检查的边界。

## 真实录制流程

录制脚本会为每次现场运行创建独立 workspace：

```bash
bash video/capture.sh prepare
```

在一个单独的终端启动固定时长录屏：

```bash
bash video/capture.sh start 150 terminal
```

在演示终端完整输入 `video/demo.sh command` 打印的命令。光标停在末尾约两秒，再按 Return。Agent 会话保持原速，终端画面直接记录 SSE 与工具调用；完成状态和运行统计来自同一次会话的 trace。

Agent 停止后，先用 `bash video/demo.sh inspect` 显示同一次运行的 trace 摘要，再录制独立验证段：

```bash
bash video/capture.sh start 30 summary-submit
bash video/capture.sh start 30 evidence-submit
bash video/demo.sh verify
```

`verify` 此时才把 hidden grader 放入 workspace，执行 21 项测试并核对四个输入文件。浏览器段通过 `video/demo.sh serve <port>` 启动 Nash 生成的页面，再真实操作键盘、pointer 和 New Game。

当前成片由以下素材组成：

- 60.5 秒终端现场运行。
- 6 秒 trace 摘要。
- 8 秒独立 grader。
- 27 秒浏览器操作。

三个终端片段和浏览器片段都保持 1× 速度。渲染脚本只做裁切、拼接、字幕烧录和静音 AAC 音轨，不重排终端事件。

## 画面与字幕原则

- 指令必须完整可读，输入后留约两秒再执行。
- 工具卡片和错误反馈保留原始顺序，运行统计直接来自同一份 trace。
- 中文字幕只陈述当前功能、运行数据和画面事实。
- 字幕位于 168 像素高的底部黑色区域，不遮挡终端或游戏。
- 浏览器画面只显示待演示页面，不出现书签、通知或其他标签页。
- 任何画面都不打开 `.env.local`，也不执行 `env`、`printenv` 或 `set`。

## 成片验收

输出文件为 `.nash/video/<run-id>/nash-demo-submission.mp4`。交付前检查：

- 时长不超过 2 分钟，文件不超过 200 MB。
- 1920×1080、30fps、H.264、`yuv420p`。
- AAC 48kHz 双声道静音轨，方便面试现场讲解。
- 完整解码无错误，开头指令、grader 结果和浏览器操作清楚可读。
- 字幕与 SRT、ASS 内容一致，不包含研发迭代或内部工作记录。
- 画面中没有密钥、个人通知和无关网页。

制作细节和命令见 [`video/README.md`](../video/README.md)。
