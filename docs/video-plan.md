# 两分钟视频先展示结果

## 视频要让评委看到什么

视频只讲一条主线：Nash 能在本地完成真实代码修改，runtime 同时保留边界和可追踪记录。架构细节只解释画面中已经出现的行为。

## 演示任务筛选标准

演示任务需要在 60 秒左右完成，包含一次有意义的反馈循环。优先选择小型已有项目中的跨文件 bug：第一次测试失败能提供新信息，Agent 修改后测试通过。纯粹生成 Todo 页面虽然直观，但无法充分展示 Agent 对既有代码和错误反馈的处理。

正式录制前至少跑五次，记录成功率和耗时。若成功率不足，先改进工具反馈和任务夹具，不通过剪辑制造一次看似顺利的运行。

## 录制准备

- 使用专门的测试 API key，录制前清空终端历史和环境变量显示。
- 固定终端尺寸、字号、主题和工作目录。
- 在干净的 demo 分支或临时副本运行，保留初始 commit。
- 关闭通知，隐藏菜单栏中的个人信息。
- 同时录制完整实时版本，剪辑版只做停顿裁切和加速。
- 准备测试通过后的 diff、JSONL 轨迹和架构图作为备用画面。
